Engineering Case Study & System Specifications

End-to-End System Pipeline

The Personal Finance Literacy RAG Assistant is engineered for high-stakes regulatory financial texts (SEC disclosures, CFPB consumer finance regulations, and Federal Reserve reserve mandates). It avoids LLM hallucinations by coupling dense semantic vector retrieval with strict prompt-level citation constraints and local offline inference.

Document Corpus (SEC/CFPB/Fed PDFs) ↳ PyMuPDF (fitz) extraction & Unicode normalization ↳ Sentence-aware Recursive Chunking (512 tokens, 64-token overlap) ↳ SHA-256 Content Hashing (Idempotent upsert & dedup) ↳ Dense Vector Embedding (BAAI/bge-small-en-v1.5, 384 dimensions) ↳ BaseRetriever Interface [LanceDB Embedded <315ms | Pinecone Serverless] ↳ Grounded Prompt Injection (Mandatory source citations) ↳ Local Ollama Inference (qwen2.5:7b / llama3.2:3b) with st.write_stream

Privacy & Local First Tenet

By integrating Ollama and embedded LanceDB, the entire ingestion, retrieval, and inference loop can run entirely air-gapped on local infrastructure without sending confidential financial queries or proprietary documents to external commercial LLM APIs.

LanceDB vs. Pinecone Serverless Benchmark

To decouple storage logic, the architecture implements an abstract BaseRetriever ABC. A side-by-side CLI tool (python rag.py --compare) runs dual queries to evaluate latency, recall consistency, and resource footprint:

Benchmark Metric LanceDB (Embedded Local) Pinecone Serverless (Cloud)
Deployment Architecture Zero-infra, embedded on-disk Apache Arrow Managed Serverless Multi-AZ Cloud
Retrieval Latency (p50) < 315 ms (Local NVMe) 410 ms (Network round-trip dependent)
Retrieval Latency (p95) < 480 ms 620 ms
Cost & Infrastructure $0.00 / Free local compute Pay-per-query & cloud storage tier
Privacy & Data Residency 100% On-Premise / Air-gapped Cloud-hosted vector index

LLM-as-a-Judge Validation

Generation quality is evaluated using an automated GPT-4o-mini judge grading two independent axes: Answer Relevance (addressing all question facets) and Context Faithfulness (strict groundedness against retrieved chunks with JSON fence stripping and retry handling).

111 Automated Unit Tests in pytest

The codebase includes a comprehensive 111-test suite written in pytest. Ingestion parsing, chunking bounds, vector conversions, retrieval ABC fallbacks, and LLM retry handlers are mocked to guarantee 100% CI pass rates without relying on external cloud APIs.
